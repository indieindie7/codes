## Hard limits
All anim/Karma/nav natives are `final`; native locomotion blend, path search and physics are not replaceable from script. No two-bone IK solver, no per-bone physics blend, no new native ReachSpecs at runtime, PathList is const (cannot add edges), SpecialCost not called for ordinary PathNodes, existing map PathNodes cannot change class. Bone controllers run after the animation (overwrite or alpha-mix the bone's local rotation; Space semantics need a test per call).

## Feasibility verdicts
- **Foot IK / foot locking: PARTIAL.** Script two-bone IK (GetBoneCoords + Trace + analytic law-of-cosines -> SetBoneRotation on UpLeg/Leg/Foot, plus PrePivot drop for the pelvis) is doable per Tick; FootStepping notify gives plant timing. Risk: frame lag (bone coords from last frame) and Space conventions; start with idle/standing on slopes and stairs, not running.
- **Procedural lean: YES.** Spine/hips SetBoneRotation from velocity change and turn rate, same mechanism as ModReact flinch and head tracking.
- **Hit-reaction additive offsets: YES (already shipped)** in ModReact; can extend to multi-bone chains.
- **Powered ragdoll: YES via impulses (prototype exists)**, no real joint motors; tune gains, crash-prone.
- **Procedural quadruped stepping: HARD.** Feasible only as a layer (per-leg IK correction + spine pitch on slopes) on top of the native gait; full procedural gait would need disabling native movement anims (`Controller.bControlAnimations` Controller.uc:21, checked in Pawn.ChangeAnimation Pawn.uc:2365; `bPhysicsAnimUpdate` Pawn.uc:271) and posing ~14 bones per tick in script.
- **Script-side tactical A* with custom costs: YES.** Graph fully readable; run time-sliced A*, then drive `MoveToward(RouteNode)` node by node (or fill RouteCache).
- **Influencing native pathfinding: YES, coarse.** ExtraCost / TransientCost / FearCost / bBlocked per node and ReachSpec.Distance per edge; set before `FindPathToward`, restore after.
