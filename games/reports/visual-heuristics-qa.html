Checking game frames against design heuristics, automatically

Design heuristics like the squint test, figure–ground and silhouette readability can be turned into numbers on screenshots. This page lists which ones can be measured, the open-source code that already does it, and a plan to run them on random frames from both games during live QA.

Squint test reference: a readable frame puts its focal point at the far end of this scale from its surroundings.

What this is for

The pilot harness can already teleport the player, turn the camera and save frames in both games. The idea is a "random prints" pass: frames from random places and angles, each scored against design heuristics, with a contact sheet that flags the weak ones. The same metrics in before/after mode tell whether a live look edit (a grade, a LUT, a shader change) made a level read better or worse.

All of it runs offline on this PC. The heuristics are rules of thumb, so the scores flag frames for a human to look at. They don't pass or fail a level by themselves.

The heuristics, as measurements

Squint testWith detail blurred away, does the focal point still stand out by light and dark?Blur and posterize to 3–5 values; measure the value contrast between the focal region and its ring; check the value histogram isn't all mid-grey.OpenCV (blur, k-means); do-it-yourself recipe in the notes

Figure–groundDo characters separate from the background?Luminance and colour (ΔE) contrast between a character mask and a dilated ring around it.AIM figure-ground metric; colour-science for ΔE
SilhouetteFilled black, can you still tell what it is and what it's doing?Mask shape statistics: solidity, convexity defects (limbs visible), outline length against area, overlap with other silhouettes.Engine mask pass (U2 fork); rembg / BiRefNet / SAM for captures
ClutterIs the frame noisy enough to hide what matters?Feature congestion, subband entropy, edge density; clutter around the focus against the frame average.visual-clutter, AIM (Rosenholtz metrics), IC9600 (private)
ColourIs the palette coherent, and does the accent mark the important thing?Palette extraction, Hasler–Süsstrunk colourfulness, hue-template harmony, colour-blind simulation.AIM, colorgram.py, colour-science

Game-specific checks

Generic models were trained on photos and UI screenshots. Frames from 2003-era games need some checks of their own, and most of them don't need machine learning:

  • Missing or default textures: large areas of exact magenta or of the engine's default checker texture.
  • Black characters: the lighting bug fixed in Unreal II this month; a character mask whose mean brightness is far below its surroundings.
  • Stretched polygons: long thin streaks found with line detection, starting at a character.
  • Z-fighting and shimmer: FLIP between two consecutive frames of a static camera; flicker shows up as speckle.
  • Gameplay glitches: GliDe (MIT) is a vision-language model pipeline for finding glitches in gameplay video; VideoGameQA-Bench (CC0) and GlitchBench give test material. EA's SEED published a CNN approach (AIIDE 2020) without code; its method (inject glitches into our own captures and train a small classifier) is easy to copy.
Since we control the renderer through the d3d8to9 fork, the best character masks come from the engine itself: a pass that draws characters in flat white. That is exact, costs nothing, and beats any segmentation model. ML masks (rembg, SAM) are for frames from games we don't render ourselves.

The pipeline

  1. Random prints. A pilot step picks random navigation points and camera angles in the current map (both games), lets the frame settle, then saves the frame plus a mask frame (characters in white). In live sessions the same step can run on demand.
  2. Score each frame. One Python tool (tools/visual_qa.py) runs the checks above and writes a JSON record per frame: saliency share on characters, figure–ground contrast, silhouette solidity, clutter, palette, HUD contrast, glitch flags.
  3. Calibrate. A baseline set from the stock game gives each metric its normal range per level, so a flag means "worse than this level usually is", not an absolute grade from a photo-trained model.
  4. Report. A contact sheet with the saliency overlay and the squint version beside each frame, sorted by how many checks it fails, plus the numbers.
  5. Before/after mode for live edits. When a look edit lands (grade, LUT, shader), the same camera positions are captured again and the report shows FLIP maps and the change in each metric.
